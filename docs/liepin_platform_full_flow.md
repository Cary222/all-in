# 猎聘（liepin）全流程（采集、评分、打招呼、投递、监测）机制说明

本文档面向维护者与系统架构师，系统性阐述猎聘（Liepin）在 AllIn 中的端到端全流程实现，包括采集机制、AI 评分、人工确认、招呼语生成、自动打招呼/投递、对话监测与安全风控防护。

---

## 1. 架构总览

AllIn 针对猎聘（Liepin）实现了与 BOSS 直聘 1:1 对齐的五维全流程生命周期闭环：

```text
┌─────────────────┐     ┌──────────────┐     ┌──────────────┐
│  1. 岗位采集    │ ──> │  2. AI 评分  │ ──> │ 3. 人工确认  │
│ (API-Fetch/DOM) │     │ (语义契合度) │     │ (确认/筛选)  │
└─────────────────┘     └──────────────┘     └──────────────┘
                                                   │
                                                   ▼
┌─────────────────┐     ┌──────────────┐     ┌──────────────┐
│ 5. 回复监听跟进 │ <── │ 4. 打招呼投递│ <── │ 招呼语生成   │
│ (消息中心/意图) │     │(模拟浏览/提交│     │ (定制求职信) │
└─────────────────┘     └──────────────┘     └──────────────┘
```

## 2. 核心模块与执行流

### 2.1 岗位采集阶段（Collect）
- **文件实现**：`src/allin/collection/platforms/liepin.py`
- **采集模式**：
  1. **API-Fetch 宿主页模式**：复用或打开猎聘搜索页（`https://www.liepin.com/zhaopin/`），在页面上下文执行同源 fetch，直接请求猎聘接口获取结构化职位卡片。
  2. **城市编码映射**：系统严格依赖 `src/allin/data/liepin_cities.json` 预置的官方城市代码（如杭州 `070020`、上海 `020000`、北京 `010000`、深圳 `040000`、广州 `030000`）。
  3. **字段标准化**：提取岗位 ID（`jobId`）、职位标题（`title`）、企业名称（`compName`）、薪资水平（`salary`）、学历/经验要求、HR/猎头称号（猎头标记、HR 称谓）及 JD 岗位描述。
  4. **降级保障**：在 API-Fetch 请求异常或触发防护时，自动切换至基于 DOM 结构的页面解析。

### 2.2 自动评分阶段（Score）
- **文件实现**：`src/allin/ai/scorer.py`
- **评分机制**：
  - 提取猎聘职位的完整 JD，与用户简历中的技能背景、项目产出与业务深度进行大模型匹配度计算。
  - AI 输出 0~100 综合得分，并附带详细的技术匹配要点与风险关注项。
  - 达标职位流转至候选池。

### 2.3 人工确认与批量操作（Confirm）
- **前端组件**：`src/allin/web/frontend/src/components/dashboard/JobsTable.tsx`
- **确认逻辑**：
  - 展示猎聘平台职位卡片与 AI 推荐理由。
  - 用户可勾选确认，点击“发送已确认岗位”加入发送流水线。

### 2.4 定制招呼语生成（Greet）
- **文件实现**：`src/allin/ai/greeter.py`
- **生成逻辑**：
  - 结合猎聘职位特征（包含 HR 招聘与猎头中介岗位的不同沟通风格）。
  - 生成专业、得体、针对性强的求职信/开聊语（约 100~200 字），凸显候选人与职位的契合度。

### 2.5 自动打招呼与投递（Deliver）
- **文件实现**：`src/allin/executor/sender.py`（`_send_liepin_greeting_once`、`LiepinSender`）
- **投递状态机流转**：
  1. **安全预检**：通过 `PlatformAccessGuard.reserve("job_page", platform="liepin")` 检查平台访问配额，触发风控即时熔断。
  2. **打开详情页**：新建标签页访问猎聘职位详情页（`https://www.liepin.com/job/...`）并等待网络就绪。
  3. **真实拟人浏览（`browse_before_greet`）**：
     - 在详情页停留随机时长（2~5 秒）；
     - 模拟平滑滚动与小幅回滚，模拟真实求职者阅读职位要求与公司介绍的过程。
  4. **异常与入口状态检测**：
     - **安全拦截检测**：识别猎聘安全中心、验证码、滑块、访问频繁或行为异常；命中后返回 `blocked` 并触发安全停止；
     - **下线检测**：识别“职位已暂停招聘”、“职位已下线”、“职位不存在”、“404”等标记，返回 `job_page_unavailable`；
     - **登录检测**：跳转到登录页或页面提示未登录时返回 `login_required`；
     - “继续聊”“已沟通”等文案只表示会话已创建，**不能作为 AI 招呼语已发送的成功凭证**。
  5. **精准点击右上角真实聊天按钮**：
     - 唯一入口为 `section.job-apply-container .job-apply-operate .apply-box > a.btn-main[data-selector="chat-chat"]`；
     - 不点击同区域灰色“投简历”按钮 `a.btn-minor[data-selector="apply-job"]`，也不点击招聘者卡片中的 `a.btn-chat`；
     - “聊一聊”和“继续聊”均需点击，以打开具体聊天弹窗；禁止点击父容器 `div.apply-box`。
  6. **聊天弹窗与跨境授权处理**：
     - 若出现“开启境外招聘方简历查阅授权”弹窗，返回 `liepin_cross_border_authorization_required`，不得把点击任意弹窗按钮误判为成功；
     - 聊天输入框固定定位为 `textarea.ant-im-input.im-ui-textarea`；
     - 将当前岗位完整 AI 招呼语写入输入框，并触发 `input`、`change` 事件；
     - 等待专用发送按钮 `button.ant-im-btn.ant-im-btn-primary.im-ui-basic-send-btn` 启用后点击；
     - 点击发送后进入等待验证状态，在气泡出现前禁止再次填入或点击，避免输入框清空与消息渲染延迟造成重复发送。
  7. **唯一成功凭证（Verification）**：
     - 只读取发送方消息气泡 `.im-ui-message-item-body.im-ui-message-item-send .im-ui-txt-content .text`；
     - 对消息气泡和当前岗位 AI 招呼语做空白标准化后，必须**完整相等**才返回 `verified=true`；
     - 平台自动发出的默认问候“觉得自己的背景和这个岗位挺匹配的，不知能否聊聊？”不算 AI 招呼语；
     - 仅按钮变为“继续聊”、出现默认问候、打开弹窗或完成点击均不算成功；验证超时返回 `liepin_send_unverified`；
     - 只有完成气泡验证后，外层发送器才把数据库状态更新为 `sent`、清空 `last_error` 并记录发送历史。

### 2.6 对话监听与跟进（Monitor）
- **文件实现**：`src/allin/executor/monitor.py`（`_check_liepin_replies`、`_open_conversation`、`_check_follow_ups`）
- **监听逻辑**：
  - 定时导航至猎聘聊天消息页面（`https://www.liepin.com/chat/`）。
  - 读取 HR/猎头的最新互动消息、已读标记及面试邀约。
  - 针对超过设定周期（如 48 小时）未获回复的岗位，调度礼貌二次跟进。

## 3. 安全防护与风控对齐标准

1. **统一工作窗口**：通过 `SendWindowChecker` 严格限定在活跃时段（如 09:00~18:00）内执行操作，非窗口期自动挂起等待。
2. **随机等待与速率限制**：投递间隔、浏览等待时间引入均匀随机化，避免时序特征。
3. **每日配额保护**：严格限制单日投递上限（通过 `throttle.daily_limit`），超限次日恢复。
4. **异常熔断机制**：连续失败或遭遇风控验证码时立即触发平台安全锁，确保账号安全。
